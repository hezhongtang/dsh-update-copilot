## 修复方案：行级实时状态保真

目标：修复两处行为缺口——① 别处发起的更新（弹窗、一键更新全部、Agent 工具、另一标签页）在匹配行内没有进度可视，只有全局横幅；② 新一轮更新开始时，行内残留的上一次「更新失败（已尝试 N 次）」不会清除，与「正在更新」横幅矛盾并存。

**纯客户端改动，服务端零变更**——live 槽已携带全部所需字段（`current.name/profile`、最新 `progress` 事件），2 秒轮询已存在于每个座位。

### 1. `client/client.js` — 新增两个纯函数（`liveRunningOf` 旁）

- `liveMatchesRow(live, name)`：`liveRunningOf(live) && live?.current?.name === name`。
- `liveRowProgress(live)`：把槽内最新事件归一化为行内现有渲染形状 `{percent, phase} | null`——`progress` 事件 → `{percent, phase}`；`retry` → `{null, 'retry'}`；`phase` → `{null, phase}`；无事件/未知 → `{null, null}`（渲染成不定进度条、无标签）。

两者加入 `__test` 导出。

### 2. `client/client.js` — `PluginRow` 三处

- **镜像进度条**：`shown = busy ? progress（自身 SSE，保持最新）: liveMatchesRow ? liveRowProgress(live) : null`；复用现有 `.duc-progress-wrap` 渲染块；标签逻辑：有 percent 显示百分比，有 phase 显示 `progressPhase` 文案，两者皆无只渲染不定进度条。
- **按钮**：`busy || liveForRow` → 同样渲染禁用的「更新中…」按钮，别处发起时该行按钮语义一致。
- **陈旧结果边沿清除**：`wasLiveForRow` ref 跟踪「该包正在被更新」的 false→true 边沿，边沿触发且 `!busy` 时 `setResult(null)`。边沿语义 + busy 守卫规避竞态：自身运行刚失败（result 刚写入、busy 刚转 false）时，2s 轮询带回的运行中旧快照不会触发边沿（运行期间 ref 已是 true），不会误清新写入的结果。只清匹配包的行，其他行的历史结果保留。

### 3. 测试 — 新增 `test/live-row.test.mjs`

把 `sse-client.test.mjs` 的 `loadBundle()`（react 桩 + ModuleLoader 求值）提取到 `test/bundle-loader.mjs` 共享（sse-client 改为 import，删除其本地副本），新测试复用。用例覆盖：`liveRowProgress` 各事件形状归一化与 null 安全；`liveMatchesRow` 的 null live / running:false / 名称不匹配 / 匹配。

### 4. 文档 — README.md / README.zh.md

「更新从不静默」段落补两句：无论谁发起，雷达中匹配的行内会出现同一根实时进度条（本行 SSE 优先，别处经轮询镜像）；新一轮更新开始时该行残留的上一次结果自动清除。

### 取舍说明

- 镜像进度经 2s 轮询，比本行 SSE 略钝——本行发起时优先走自身 SSE 流（busy 分支），不受影响；别处发起时 2s 粒度足够。
- 不清其他行的结果：失败历史对未受影响的包仍是真话，只有匹配包开始新一轮更新才视为旧结果过期。
- LiveBanner 保留：覆盖更新目标不在可见列表（折叠组、隐藏行）时的全局可见性。
