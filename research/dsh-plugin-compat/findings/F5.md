# F5: 同类升级工具的兼容改进

## Findings

### [1] npm-check-updates 的 `--doctor` 模式是「先乐观全升、失败则二分回退」的 breaking-change 检测器：先跑基线测试，再全量升级，失败后逐包 `npm install --no-save` + 测试，把坏包剔除，最后只把通过的升级写回 package.json。
- quote: "Iteratively installs upgrades and runs your project's tests to identify breaking upgrades. Reverts broken upgrades and updates package.json with working upgrades."
- url: https://github.com/raineorshine/npm-check-updates
- source_type: primary
- published: unknown (as of 2026-09 fetch)
- confidence: high

### [2] npm-check-updates 的 `--peer` 是 peer-graph 健康门禁：升级时按已安装包的 peerDependencies 约束过滤候选版本，只保留仍满足 peer 约束的最高版本，而不是盲目追 latest。
- quote: "Check peer dependencies of installed packages and filter updates to compatible versions. … ncu upgrades packages to the highest version that still adheres to the peer dependency constraints"
- url: https://github.com/raineorshine/npm-check-updates
- source_type: primary
- published: unknown (as of 2026-09 fetch)
- confidence: high

### [3] npm-check-updates 的 `--cooldown` / `min-release-age` 是「发布冷却期」semver gate：版本必须发布满 N 天才可升级；默认 `--target latest` 会在 latest 落在冷却期内时回退到仍满足冷却的最高版本，`--target @latest` 则整包跳过。
- quote: "The cooldown option helps protect against supply chain attacks by requiring package versions to be published at least the given amount of time before considering them for upgrade. … ncu falls back to the greatest version that passes the cooldown threshold."
- url: https://github.com/raineorshine/npm-check-updates
- source_type: primary
- published: unknown (as of 2026-09 fetch)
- confidence: high

### [4] npm-check-updates 的 `--target` + `filterResults`/`--reject`/`--rejectVersion` 构成分层 semver gate：`semver` 永不越出声明 range，`minor`/`patch` 锁 major，`filterResults` 可在取回新版本后按 major 跳变拒绝，`--enginesNode` 进一步只保留满足 `engines.node` 的包。
- quote: "With `--target semver`, update according to your specified semver version ranges … An explicit upper bound is respected and preserved, so the upgrade never exceeds it"
- url: https://github.com/raineorshine/npm-check-updates
- source_type: primary
- published: unknown (as of 2026-09 fetch)
- confidence: high

### [5] Renovate 的 `rollbackPrs` 是「registry yank 后降级」能力：当当前版本从 registry 消失时，自动提议降到仍存在的次高版本；默认关闭，官方建议用 `packageRules` 选择性开启而非全局开启。
- quote: "Renovate's \"rollback\" feature exists to propose a downgrade to the next-highest release if the current release is no longer found in the registry. Renovate does not create these rollback PRs by default"
- url: https://raw.githubusercontent.com/renovatebot/renovate/main/docs/usage/configuration-options.md
- source_type: primary
- published: unknown (as of 2026-09 fetch)
- confidence: high

### [6] Renovate 的 `postUpgradeTasks` 是「升级后 codemod/迁移钩子」：依赖更新后、提交前执行命令（如 `tslint --fix`、`make generate`），支持 `executionMode: update|branch`、`fileFilters` 白名单、`installTools` 按 constraints 装工具；默认因安全被全局 `allowedCommands` 拦截。
- quote: "Post-upgrade tasks are commands that are executed by Renovate after a dependency has been updated but before the commit is created. … Post-upgrade tasks are blocked by default for security reasons"
- url: https://raw.githubusercontent.com/renovatebot/renovate/main/docs/usage/configuration-options.md
- source_type: primary
- published: unknown (as of 2026-09 fetch)
- confidence: high

### [7] Renovate 的 `minimumReleaseAge` + `minimumReleaseAgeBehaviour` + `minimumReleaseAgeBuffer` 是三层稳定性门禁：未满冷却期的版本挂 pending status（`renovate/stability-days`）阻止 automerge；`timestamp-required` 可要求必须有 release timestamp 才算 stable；buffer 默认 30 分钟以对齐 companion 包晚发布与包管理器自己的冷却。
- quote: "When the time passed since the release is _less_ than the set `minimumReleaseAge`: Renovate adds a \"pending\" status check to that update's branch. … By default, Renovate uses a buffer of 30 minutes."
- url: https://raw.githubusercontent.com/renovatebot/renovate/main/docs/usage/configuration-options.md
- source_type: primary
- published: unknown (as of 2026-09 fetch)
- confidence: high

### [8] Renovate 的 `constraintsFiltering: strict` 是引擎/运行时兼容预检：仓库 `engines`（或 `constraints.python` 等）必须是候选版本自身 constraint 的子集才放行，否则静默过滤；官方警告不要与 `rollbackPrs` 同时开启，否则当前版本可能因不兼容被误回滚。
- quote: "If so, filter out this release unless the repository constraint is a _subset_ of the release constraint … Do _not_ enable `rollbackPrs` at the same time (otherwise your _current_ version may be rolled back if it's incompatible)"
- url: https://raw.githubusercontent.com/renovatebot/renovate/main/docs/usage/configuration-options.md
- source_type: primary
- published: unknown (as of 2026-09 fetch)
- confidence: high

### [9] Renovate 用 `separateMajorMinor` + `maxMajorIncrement` 做 semver gate 与爆炸半径控制：major/minor 默认拆 PR（关掉 major PR 后 2.x 仍会持续更新且不复活 major PR）；`maxMajorIncrement` 过滤 CalVer 跳变（如 `2025.0.0`）并可 per-package 设为 0 表示不限 major 步长。
- quote: "For example, if you're on version `19.0.0`, Renovate will upgrade to `22.0.0` but filter out versions like `999.0.0` and `2025.0.0`."
- url: https://raw.githubusercontent.com/renovatebot/renovate/main/docs/usage/configuration-options.md
- source_type: primary
- published: unknown (as of 2026-09 fetch)
- confidence: high

### [10] VS Code 扩展用 `engines.vscode` 做 host-兼容 gate：`^1.8.0` 只装到含所需 API 的客户端；Insiders 可用日期 tag `^1.56.0-20210428` 精确限定构建；Marketplace 据此对不同客户端分发不同可用版本，用户在 Stable 上要等 host 到 1.9.0 才收到依赖新 API 的更新。
- quote: "You can use the `engines.vscode` property to ensure the extension only gets installed for clients that contain the API you depend on. … Users with the VS Code Stable will only get the update when the Stable release reaches version `1.9.0`."
- url: https://code.visualstudio.com/api/working-with-extensions/publishing-extension
- source_type: primary
- published: 2026-09-16
- confidence: high

### [11] VS Code 用「偶数 minor = 正式 / 奇数 minor = 预发布」的版本号约定做 canary 通道，并用 deprecation + 可选 replacement/setting 的一键 Migrate 按钮做迁移引导：不会自动卸载已弃用扩展，但 UI 会提示替代扩展或替代设置。
- quote: "we recommend that extensions use `major.EVEN_NUMBER.patch` for release versions and `major.ODD_NUMBER.patch` for pre-release versions. … If a deprecated extension has an alternative extension, or a setting, VS Code will show a **Migrate** button to help you quickly switch"
- url: https://code.visualstudio.com/api/working-with-extensions/publishing-extension
- source_type: primary
- published: 2026-09-16
- confidence: high

### [12] pnpm 把「升级会写什么」与「如何分级」做成了可预检契约：`pnpm outdated --compatible` 只列出仍满足 package.json 规格的版本；`pnpm up --changeset` 自动为 deps 变更写 patch changeset、为 peerDeps 变更写 major changeset（把 peer 破坏视为 major）；`--no-save` 可只动 lockfile 做 dry-run。
- quote: "Prints only versions that satisfy specifications in `package.json`. … write a change intent … declaring a `patch` bump for every workspace package whose `dependencies` or `optionalDependencies` were changed by the update, and a `major` bump when its `peerDependencies` changed."
- url: https://pnpm.io/cli/outdated ; https://pnpm.io/cli/update
- source_type: primary
- published: unknown (pnpm 12.x docs, as of 2026-09 fetch)
- confidence: high

### [13] Homebrew 把「可逆性」做进 CLI 原语：`pin`/`unpin` 锁住包不被 `brew upgrade` 带跑；`migrate`（含 `--dry-run`）处理改名包；`cleanup --dry-run`/`autoremove --dry-run` 预演清理；多 keg 并存（Cellar 下多版本）+ `brew bundle dump` 快照已装状态，构成隐式 rollback 面（旧 keg 仍在可再 link）。
- quote: "Pin the specified package, preventing it from being upgraded when issuing the `brew upgrade` … Migrate renamed packages to new names … `-n`, `--dry-run` Show what would be migrated, but do not actually migrate anything."
- url: https://docs.brew.sh/Manpage
- source_type: primary
- published: unknown (as of 2026-09 fetch)
- confidence: high

### [14] update-notifier 的设计取舍是「只通知、不自动更」：异步子进程检查 + 间隔缓存（默认 1 天）不拖慢启动，返回 `type: latest|major|minor|patch|prerelease|build` 供调用方分级提示；用户可用 `NO_UPDATE_NOTIFIER` / `--no-update-notifier` / configstore optOut 关闭，CI 与 `NODE_ENV=test` 自动跳过——即 host+plugin 更新器把「打扰控制」和「破坏级别标注」放在 preflight 之前。
- quote: "Whenever you initiate the update notifier and it's not within the interval threshold, it will asynchronously check with npm in the background … `type` *(string)* - Type of the current update. Possible values: `latest`, `major`, `minor`, `patch`, `prerelease`, `build`."
- url: https://raw.githubusercontent.com/yeoman/update-notifier/main/readme.md
- source_type: primary
- published: unknown (as of 2026-09 fetch)
- confidence: high

### [15] Koishi 插件市场走 npm 命名约定做 host↔plugin 解析（`foo` → `@koishijs/plugin-foo` / `koishi-plugin-foo`，`@foo/bar` → `@foo/koishi-plugin-bar`），并靠「默认导出优先于整体导出」+ 子插件独立热重载来缩小升级/重载爆炸半径——这是 host+plugin 更新器可迁移的「命名映射 + 细粒度 reload」模式，但未见独立的 semver gate 或一键 rollback。
- quote: "对于 foo，我们将尝试读取 @koishijs/plugin-foo 和 koishi-plugin-foo … 只要模块提供了默认导出，Koishi 就会尝试加载这个默认导出，而不是导出整体。"
- url: https://koishi.chat/zh-CN/guide/plugin.html
- source_type: primary
- published: unknown (as of 2026-09 fetch)
- confidence: medium

## Dead ends
- Koishi 插件市场页（koishi.chat/market）与「插件更新/兼容矩阵」专页未深挖到 semver/rollback 机制；仅有插件解析与热重载文档。
- 搜索结果中的 zenn.dev / pkgpulse / openreplay / dedimarco 等二手对比文未 fetch 引用（内容农场/SEO 倾向，按规则丢弃）。
- Renovate `rollback`/`postUpgradeTasks` 的 HTML 页被 TOC 淹没且截断；改用 raw GitHub markdown 拿到权威段落，效果等价 primary。
- 未专门调研 Chrome/Firefox 扩展 MV2→MV3 迁移、Docker/HELM hook、或 Firefox 附加组件的兼容性白名单——时间/调用预算内未展开。

## Suggested follow-ups
- Renovate `postUpgradeTasks.allowedCommands` 的安全模型（self-hosted admin 如何 allowlist codemod），以及与 npm `postinstall` 迁移脚本的对比。
- VS Code 扩展「同一扩展跨 engines 矩阵」的分发细节（Marketplace 如何对旧客户端隐藏新版本），可映射到 dsh 多版本 host 的插件可见性。
- Homebrew `keg` 多版本并存 + `opt` 符号链接的 rollback 状态机，是否可直接借用为 dsh-update-copilot 的一键回退实现。
