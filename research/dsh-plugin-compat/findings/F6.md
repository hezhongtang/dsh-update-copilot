# F6: 社区真实故障与经验

## Findings

### [1] 升级 host 到 0.1.1-rc.2 后，旧 adapter 契约的第三方插件在首次调用时报 `registration.adapter.prepareCall is not a function`，且无任何启动期/升级期兼容检查
- quote: "Upgrading `@deepseek-ai/dsh` from `0.1.0-rc.6` to `0.1.1-rc.2` silently breaks third-party plugins that were written against the rc.6/rc.7 adapter contract. In our case, the community plugin `dsh-vision-router` v1.6.2 crashed the web UI on the first message with: registration.adapter.prepareCall is not a function"
- url: https://github.com/deepseek-ai/deepseek-harness/discussions/4013
- source_type: community
- published: 2026-08-22
- confidence: high

### [2] 对 adapter 契约变更的验证修复是升级插件到实现新方法的版本（dsh-vision-router v1.6.2 → v1.7.6, commit dae05e10），而非 host 侧回滚
- quote: "Workaround (verified) Upgrading the plugin to v1.7.6 (commit `dae05e10`, \"support DSH 0.1.1 prepareCall adapter contract\") fixes the crash."
- url: https://github.com/deepseek-ai/deepseek-harness/discussions/4013
- source_type: community
- published: 2026-08-22
- confidence: high

### [3] 跨代兼容的正确手法是 peerDependency 绑 host 的 `LlmAdapter` 基类并继承方法，而不是自己实现 `prepareCall`；对象字面量 adapter 是崩溃根因
- quote: "The fix is not \"implement `prepareCall`\", it's \"inherit it\" ... build the adapter on the host's own `LlmAdapter` base class, resolved through a peer dependency rather than a hard one ... The failure mode you saw comes from adapters registered as **plain object literals** — an object literal has no base class to inherit from"
- url: https://github.com/deepseek-ai/deepseek-harness/discussions/4013
- source_type: community
- published: 2026-08-26
- confidence: high

### [4] 兼容探测应 probe capability（`typeof LlmAdapter.prototype.prepareCall === 'function'`）而非 version string；且同一代际变更还搬走了 `system-prompt/assemble`、`tools/pre-execute` waterfall，单查 adapter 方法不够
- quote: "probe the capability, never the version string. We branch on typeof LlmAdapter.prototype.prepareCall === 'function' ... the same generation gap moved several waterfalls (`system-prompt/assemble`, `tools/pre-execute`) from agent-loop into their own subsystems, and changed attachment storage to re-encode images rather than store bytes verbatim."
- url: https://github.com/deepseek-ai/deepseek-harness/discussions/4013
- source_type: community
- published: 2026-08-26
- confidence: high

### [5] 文档化的 host API `ctx.subagents.registerContinuableSetup(...)` 在 0.1.1-rc.1 → 0.1.2-rc.1 之间整段消失，社区插件无法启动且 runtime 无任何命名错误或版本探测面
- quote: "`ctx.subagents.registerContinuableSetup(...)` — part of the documented continuable-subagent surface in 0.1.1-rc.1 ... no longer exists anywhere in 0.1.2-rc.1 after the subagent/session rework. A community agent-teams plugin that calls it cannot start against 0.1.2 and is now disabled ... there is no host version or capability surface to query."
- url: https://github.com/deepseek-ai/deepseek-harness/discussions/6540
- source_type: community
- published: 2026-09-13
- confidence: high

### [6] 社区对 host 稳定性的明确诉求：暴露 `ctx.host.apiVersion`/capability set、被删 API 保留一版 throwing stub、每版发布 Host API change notes、manifest 声明 `"dsh": ">=0.1.1 <0.1.2"` 兼容范围并在 boot 打 loud mismatch warning
- quote: "Expose a host API version / capability set to plugins (e.g. `ctx.host.apiVersion` or a capability list) ... A one-release deprecation window where feasible: keep removed APIs as throwing stubs for one rc cycle ... Per-release \"Host API changes\" notes ... let plugins declare a compatibility range in their manifest (e.g. `\"dsh\": \">=0.1.1 <0.1.2\"`), and have boot log a loud mismatch warning"
- url: https://github.com/deepseek-ai/deepseek-harness/discussions/6540
- source_type: community
- published: 2026-09-13
- confidence: high

### [7] 半升级 host/plugin 对的两种硬失败可被预检三分类捕获：link-time（`export not found` / `does not provide an export named …`）、mount-time（`failed to apply loader entry` / `… requires … in the Host scope` / `duplicate loader entry id`）、run-time（`… is not a function`）
- quote: "LAYER link-time ... `does not provide an export named …`, `SyntaxError: The requested module …` ... LAYER mount-time ... `failed to apply loader entry …`, `… requires … in the Host scope`, `duplicate loader entry id: …` ... LAYER run-time ... `… is not a function` after a successful handshake"
- url: https://github.com/grunmin/dsh-acp-enhanced
- source_type: community
- published: 2026-09 (unknown exact day)
- confidence: high

### [8] dsh-acp-enhanced 0.7.0 → 0.9.0 半升级的实证：CLI 先升 bridge 后留 → `session/new` 报 `tool-subagent: modelSelectionSettings requires … in the Host scope`；bridge 先升 CLI 后留 → profile 装载期 `subpath './model-selection-settings' is not defined by "exports"`
- quote: "CLI first, bridge left at 0.7.0 ... every `session/new` fails with an Internal error (`tool-subagent: modelSelectionSettings requires … in the Host scope`) ... Bridge first, CLI left behind ... The profile dies while loading (`… subpath './model-selection-settings' is not defined by \"exports\"`)."
- url: https://github.com/grunmin/dsh-acp-enhanced
- source_type: community
- published: 2026-09 (unknown exact day)
- confidence: high

### [9] Cordis loader 是单点故障域：`cordis-plugin-loader` await 每个 entry 并 rethrow 第一个 rejection，一行 unloadable row 会拖垮整棵 plugin tree（可能先答完 ACP initialize 再死，客户端表现为 opaque hang）
- quote: "The profile is a **single failure domain**. `cordis-plugin-loader` awaits every entry and rethrows the first rejection, so one unloadable row aborts the whole plugin tree: the process may even answer the ACP `initialize` handshake first and die right after, which a client reports as an opaque hang, not an error."
- url: https://github.com/grunmin/dsh-acp-enhanced
- source_type: community
- published: 2026-09 (unknown exact day)
- confidence: high

### [10] DevDependency 用 exact pin 与 CLI 的 range-resolved closure 混用会产生 split closure，profile boot 以 export-not-found 失败；增量 pnpm install 还会留下 stale peer，boot/session/new 通过但首轮 turn 在 `PersistenceCoordinator` 上 `TypeError: Cannot read properties of undefined (reading 'length')`
- quote: "exact patch pins here mixed with the CLI's range-resolved closure produce a split closure (two versions of one name) that breaks profile boots with export-not-found errors ... an incremental install both leaves stale store entries poisoning the profile heal AND retains stale lockfile peer resolutions — bumping 0.1.2-alpha.2 → 0.1.2-rc.1 in place left `dsh-session-persistence@0.1.2-alpha.3` (old-generation peers) wired into the rc.1 packages' snapshots, which passes boot and session/new and only breaks the first turn"
- url: https://github.com/grunmin/dsh-acp-enhanced
- source_type: community
- published: 2026-09 (unknown exact day)
- confidence: high

### [11] 插件拉进第二份 `@deepseek-ai/dsh-tools` 会拆开 `Symbol` key，导致每次 tool call 报 `Cannot read properties of undefined (reading 'prepare')`，且崩溃会毒化 session（`tool/call` 无配对 `tool/result`，后续 turn 永久 400）；`pnpm overrides` 钉版本无效，须物理去重
- quote: "When two copies are loaded, the `ToolRuntime` behind `ctx.tools` was built by one copy and stamped its scheduler onto the instance under *that* copy's symbol, while the agent loop reads with the *other* copy's symbol ... `pnpm overrides` pinning a single version does **not** fix it. Overrides pin versions; they don't remove physical duplicates"
- url: https://dshdocs.com/troubleshooting/reading-prepare-plugin-crash/
- source_type: secondary
- published: 2026-09-14
- confidence: high

### [12] 用 pnpm 装 host 会导致 `plugin tree failed to load: failed to import loader entry … ERR_MODULE_NOT_FOUND`（stock web profile 141 行可挂 4–~200 条失败）；同机 npm i -g / npx 正常，修复是改用 npm 或 pnpm `nodeLinker: hoisted` + `autoInstallPeers: true`
- quote: "Error: dsh: plugin tree failed to load: failed to apply loader entry include(cordis:include): loader entries failed to apply ... The near-universal trigger: **`dsh` was installed with pnpm.** ... The same version on the same machine via `npm i -g` or `npx @deepseek-ai/dsh web` boots normally."
