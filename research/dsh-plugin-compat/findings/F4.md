# F4: 版本/peer/semver 兼容坑

## Findings

### [1] SemVer 规定 0.y.z 属于初始开发阶段，公共 API 不应视为稳定，任何东西都可能随时变更
- quote: "Major version zero (0.y.z) is for initial development. Anything MAY change at any time. The public API SHOULD NOT be considered stable."
- url: https://semver.org/
- source_type: primary
- published: SemVer 2.0.0
- confidence: high

### [2] SemVer 建议 0.x 阶段从 0.1.0 起步、每次发版递增 minor；FAQ 同时把「每天改 API」明确归入 0.y.z
- quote: "The simplest thing to do is start your initial development release at 0.1.0 and then increment the minor version for each subsequent release. … Major version zero is all about rapid development. If you're changing the API every day you should either still be in version 0.y.z …"
- url: https://semver.org/
- source_type: primary
- published: SemVer 2.0.0
- confidence: high

### [3] SemVer §9/§11 规定 prerelease 优先级低于同号正式版，且「不稳定、可能不满足其关联正式版所宣称的兼容性」
- quote: "Pre-release versions have a lower precedence than the associated normal version. A pre-release version indicates that the version is unstable and might not satisfy the intended compatibility requirements as denoted by its associated normal version."
- url: https://semver.org/
- source_type: primary
- published: SemVer 2.0.0
- confidence: high

### [4] node-semver 中 `^0.1.0` 脱糖为 `>=0.1.0 <0.2.0-0`，0.x 的 caret 把 minor 当破坏性边界、只放行 patch；`^0.0.x` 更紧到只放行同一个 0.0.z
- quote: "Allows changes that do not modify the left-most non-zero element … patch updates for versions 0.X >=0.1.0, and *no* updates for versions 0.0.X. … `^0.2.3` := `>=0.2.3 <0.3.0-0` … `^0.0.3` := `>=0.0.3 <0.0.4-0`"
- url: https://github.com/npm/node-semver
- source_type: primary
- published: unknown (node-semver main README)
- confidence: high

### [5] node-semver 默认规则：带 prerelease 的版本只有在同一 `[major, minor, patch]` 元组上也有 prerelease 比较符时才能入范围，因此 `^0.1.0-rc.8` 默认不匹配 `0.1.2-rc.1`
- quote: "If a version has a prerelease tag (for example, `1.2.3-alpha.3`) then it will only be allowed to satisfy comparator sets if at least one comparator with the same `[major, minor, patch]` tuple also has a prerelease tag. … `>1.2.3-alpha.3` … would *not* be satisfied by `3.4.5-alpha.9`"
- url: https://github.com/npm/node-semver
- source_type: primary
- published: unknown (node-semver main README)
- confidence: high

### [6] 用 npm 自带 node-semver 实测：`satisfies('0.1.2-rc.1','^0.1.0-rc.8')` 为 false，开 `includePrerelease` 后为 true；同元组 `0.1.0-rc.8`/`0.1.0-rc.10` 与正式 `0.1.1` 可匹配，`0.2.0-rc.1` 与 `0.2.0` 均不匹配
- quote: "0.1.2-rc.1 | ^0.1.0-rc.8 | def=false | inc=true … 0.1.1 | ^0.1.0-rc.8 | def=true | inc=true … 0.2.0-rc.1 | ^0.1.0-rc.8 | def=false | inc=false … exp ^0.1.0-rc.8 >=0.1.0-rc.8 <0.2.0-0"
- url: https://github.com/npm/node-semver
- source_type: primary
- published: 2026-09-22 (本地 node v26.5.0 + /opt/homebrew/lib/node_modules/npm/node_modules/semver 实测)
- confidence: high

### [7] node-semver 把 prerelease 默认排除解释为「用户只 opt-in 了那一批 alpha/beta/rc」，并提供 `includePrerelease` 选项关闭该行为
- quote: "a user who has opted into using a prerelease version has indicated the intent to use *that specific* set of alpha/beta/rc versions. … this behavior can be suppressed … by setting the `includePrerelease` flag"
- url: https://github.com/npm/node-semver
- source_type: primary
- published: unknown (node-semver main README)
- confidence: high

### [8] npm 官方把 peerDependencies 定位为 plugin↔host 兼容声明，并要求插件侧范围「尽可能宽」、不要锁到具体 patch；npm v3–6 只警告，npm v7+ 默认安装 peer
- quote: "In some cases, you want to express the compatibility of your package with a host tool or library … This is usually referred to as a *plugin*. … make sure your plugin requirement is as broad as possible, and not to lock it down to specific patch versions. … As of npm v7, peerDependencies *are* installed by default."
- url: https://docs.npmjs.com/cli/v11/configuring-npm/package-json
- source_type: primary
- published: 2025-10 前后（npm Docs CLI v11.19.1）
- confidence: high

### [9] npm 官方示例用 `"@npm/tea": "2.x"` 表达「仅兼容 host 第二 major」，并指出冲突的插件 peer 要求会导致安装树无法解析而报错
- quote: "This ensures your package `@npm/tea-latte` can be installed *along* with the second major version of the host package `@npm/tea` only. … Trying to install another plugin with a conflicting requirement may cause an error if the tree cannot be resolved correctly."
- url: https://docs.npmjs.com/cli/v11/configuring-npm/package-json
- source_type: primary
- published: 2025-10 前后（npm Docs CLI v11.19.1）
- confidence: high

### [10] `peerDependenciesMeta.optional: true` 会让 npm 不自动安装该 peer，是多 host/可选宿主场景的官方逃生舱
- quote: "Specifically, it allows peer dependencies to be marked as optional. Npm will not automatically install optional peer dependencies. This allows you to integrate and interact with a variety of host packages without requiring all of them to be installed."
- url: https://docs.npmjs.com/cli/v11/configuring-npm/package-json
- source_type: primary
- published: 2025-10 前后（npm Docs CLI v11.19.1）
- confidence: high

### [11] pnpm `autoInstallPeers` 默认 true，会挑「满足 peer 范围的最高版本」；若多个包 peer 范围冲突（如 `react@^16` vs `react@^17`）则完全不自动安装，只打警告
- quote: "When `true`, any missing non-optional peer dependencies are automatically installed. The version picked is the highest one satisfying the peer range. … If there are conflicting version requirements for a peer dependency from different packages, pnpm will not install any version of the conflicting peer dependency automatically. Instead, a warning is printed."
- url: https://pnpm.io/settings/peer-dependencies
- source_type: primary
- published: unknown (pnpm 12.x docs)
- confidence: high

### [12] pnpm `strictPeerDependencies` 默认 false（缺/不合法 peer 只警告）；开启后安装会直接失败——预检必须区分「警告可跑」和「硬失败」
- quote: "Default: **false** … If this is enabled, commands will fail if there is a missing or invalid peer dependency in the tree."
- url: https://pnpm.io/settings/peer-dependencies
- source_type: primary
- published: unknown (pnpm 12.x docs)
- confidence: high

### [13] pnpm 提供 `peerDependencyRules.ignoreMissing` / `allowedVersions` / `allowAny`，是宿主 0.x 快速迭代时压制 peer 不匹配告警的业界解法（例如 `allowAny: ["@deepseek-ai/*"]`）
- quote: "`allowAny` is an array of package name patterns, any peer dependency matching the pattern will be resolved from any version, regardless of the range specified in `peerDependencies`. … Unmet peer dependency warnings will not be printed for peer dependencies of the specified range."
- url: https://pnpm.io/settings/peer-dependencies
- source_type: primary
- published: unknown (pnpm 12.x docs)
- confidence: high

### [14] npm dist-tag：裸 `npm install <pkg>` 解析到 `latest` 标签；`npm publish` 默认把 `latest` 指到刚发布的版本，除非 `--tag` 指定其他标签；prerelease 流通常走 `next`/`beta`/`canary` 而 `latest` 仍指旧稳定版
- quote: "Publishing a package sets the `latest` tag to the published version unless the `--tag` option is used. For example, `npm publish --tag=beta`. By default, `npm install <pkg>` … installs the `latest` tag. … Typically, projects only use the `latest` tag for stable release versions, and use other tags for unstable versions such as prereleases."
- url: https://docs.npmjs.com/cli/v11/commands/npm-dist-tag
- source_type: primary
- published: 2025-10-04（npm dist-tag 文档 last edited）
- confidence: high

### [15] npm dist-tag 标签与版本号同命名空间，可被当成 semver range 的标签（如 `v1.4`）会被拒绝；标签命名须避开数字/`v` 开头，否则 monorepo 子包 dist-tag 流程更易踩坑
- quote: "Tags must share a namespace with version numbers … Tags that can be interpreted as valid semver ranges will be rejected. For example, `v1.4` cannot be used as a tag … The simplest way to avoid semver problems with tags is to use tags that do not begin with a number or the letter `v`."
- url: https://docs.npmjs.com/cli/v11/commands/npm-dist-tag
- source_type: primary
- published: 2025-10-04（npm dist-tag 文档 last edited）
- confidence: high

### [16] GitHub commit pin：package-spec 允许 `npm/cli#c12ea07`、`git+ssh://git@github.com:npm/cli#v6.0.0`、`#semver:^5.0`；git 依赖若含 build/prepare 等脚本或 workspaces 会在每次安装时克隆临时目录并重建
- quote: "If `#<commit-ish>` is provided, it will be used to clone exactly that commit. If the commit-ish has the format `#semver:<semver>` … npm will look for any tags or refs matching that range … If your git repository includes pre-built artifacts, you will likely want to make sure that none of the above scripts are defined, or your dependency will be rebuilt for every installation."
- url: https://docs.npmjs.com/cli/v11/configuring-npm/package-json
- source_type: primary
- published: 2025-10 前后（npm Docs CLI v11.19.1）
- confidence: high

### [17] 本地 `file:`/文件夹检出不会自动安装其自身依赖，且官方明确不应发布到 registry——link: 联调通过不代表用户侧安装图正确
- quote: "This feature is helpful for local offline development … but should not be used when publishing your package to the public registry. *note*: Packages linked by local path will not have their own dependencies installed when `npm install` is run. You must run `npm install` from inside the local path itself."
- url: https://docs.npmjs.com/cli/v11/configuring-npm/package-json
- source_type: primary
- published: 2025-10 前后（npm Docs CLI v11.19.1）
- confidence: high

### [18] package-spec 将本地目录写作 `./my-package` 或 `/opt/npm/my-package`（相对/绝对路径），git 简写可 pin 到 commit（`npm/cli#c12ea07`）——升级误判常来自「本地/link 联调版本」与「registry/git 解析版本」不一致
- quote: "This refers to a package on the local filesystem. Specifically this is a folder with a `package.json` file in it. … `npm/cli#c12ea07`"
- url: https://docs.npmjs.com/cli/v11/using-npm/package-spec
- source_type: primary
- published: 2026-02-11（package-spec 文档 last edited）
- confidence: high
