## Dead ends
- dsh-plugin-hub 的多个同名仓库（dshplugin、cclank、helloHupc、wingsky-1）多为聚合站/内容农场式目录页，未提供比 pax-beehive schemas 更结构化的破坏点字段；仅 pax-beehive/dsh-hub-cli 的 Zod 契约值得吸收。
- Web 搜索「dsh-compat-guard release notes 127」等混杂 SEO 页（tool.lu、magicnetworld、dsh-plugins-mp.com），未引用；一手以 GitHub 仓库 README/源码为准。
- grunmin/dsh-acp-enhanced 的 docs/plans/* 为迁移过程记录（2026-09-01 alpha.2、2026-09-19 0.1.3+、2026-09-20 public-api-only），非机检 schema，未单列 finding。
- dsh-compat-guard 的 lib/formats.json 自承「seed data only」，0.1.0-rc.7 sessionFormat 仍为 unknown——存储指纹覆盖不全，不能当权威表。

## Suggested follow-ups
- 对照 dsh-update-copilot 现有预检输出，列出可直接落地的字段映射：pre-flight-patterns.json 七类 regex → 静态扫描项；compat/schema.json 的 pass/fail/unknown+evidence → 兼容矩阵列；acp-doctor 三层 stderr 签名 → 启动失败分类器。
- 核对 oh-my-dsh 卡片 frontmatter 的 validate.mjs 规则（cardCount/idPrefix/必填字段）是否可被 update-copilot 复用为「版本对→卡片」索引的数据源，以及 corridor 缺边时的 stop 规则（README 明确「when a corridor edge is missing, stop the automatic migration」）。
- 评估把 pax-beehive compatibilitySchema 的 surfaces/hmr/entryIds/before/after 字段写进 update-copilot 的插件清单采集，作为 loader entry 契约预检的输入。
