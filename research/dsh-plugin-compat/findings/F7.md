## Dead ends
- 官方文档**没有**独立的「plugin migration guide」或「breaking change policy」专页；仅有 README 的 developer-preview 兼容性警告 + 产品页「API 持续迭代」表述。
- 官方文档**没有** `dshTarget` 字段或正式 compat/peer range 校验机制；peer 版本范围被明确「不校验」。社区站 alldsh.com 提到 dshTarget，但未抓取、来源不明，不作为证据。
- 搜索 "dsh plugin CLI bundle patch client inject peer compat" 的第三路查询被无关词典/教育结果污染（Merriam-Webster、ACEP 等），丢弃。
- GitHub issue 搜索 `plugin compat` 在 deepseek-ai/deepseek-harness 返回 0 结果（issue 创建受限）；搜索摘要提到的「0.1.1 升级静默破坏第三方插件」issue 未拿到完整 URL，未引用。
- 未取得官方 `make-dsh-plugin` skill 本体（社区文档称其为 plugin-registry 自带官方引导）。
- extensions-runtime 社区路径 404；client inject 官方表述以 client-modules 参考为准。

## Suggested follow-ups
- 对照 dsh-update-copilot 的 `dsh.client.inject` + `exports["./client"]` 与官方 `WebBootEntry` 语义，核对 v0.7.0 是否仍匹配 0.1.5–0.1.7 的 client-modules 扫描约定。
- 官方 peer 不校验版本范围 → 预检应以「声明的 peerDependencies 字符串」+「宿主实际安装的 @deepseek-ai/* 版本」做启发式矩阵，而非依赖 loader 拒绝。
- 跟踪 0.1.2→0.1.5 社区迁移表中的包级改名/移除（尤其 `dsh-client-runtime`、`dsh-host-apiproxy`），作为 update-copilot 兼容模型的 breaking 清单来源。
